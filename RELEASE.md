# Release

Public releases must start from the reviewed standalone payload, not from a local development history that contains retired installers, machine paths, media, task records, or credentials.

## Release gate

1. Confirm the public maintainer name in `NOTICE.txt`, the version, the macOS Apple Silicon and native Windows 11 x64 implementation contracts, and the default backend contract. Treat Linux as preview.
2. On the reviewed source worktree, run the payload audit without `--history`, then exercise the deterministic platform entrypoints that are available on the maintainer host:

   | Platform | Install | Status | Tests |
   | --- | --- | --- | --- |
   | macOS Apple Silicon | `./install --with-mosaic` | `./video-replacer status --json` | `./video-replacer-test` |
   | native Windows 11 x64 | `.\install.cmd --with-mosaic` | `.\video-replacer.cmd status --json` | `.\video-replacer-test.cmd` |

   Run the no-backend Doctor through the platform virtual environment before online setup. Windows CI also downloads the pinned Dreamina artifact from its reviewed upstream URL, checks its SHA-256, and invokes `version`; that is an artifact/upstream-availability Gate only. Deterministic tests exercise the Windows Codex package/release verifier with fixtures, but they do not prove the candidate host's installed `codex.exe`, live `releases.openai.com` response, account, or native request surface. These checks do not satisfy the real-platform gates below.
3. Review `git status`, every intended public path, `git diff --check`, executable modes, license files, and `tools/release_audit.py --list-files`. Runtime, media, local catalogs, outputs, credentials, logs, databases, signed URLs and task IDs must be absent.
4. Copy exactly that reviewed file list, without `.git`, into a new temporary directory and initialize an independent Git repository there. Create one clean root commit. Do not use an orphan or release branch inside the legacy repository: `--history` scans every reachable ref and would still see the retired objects.
5. Clone that independent candidate commit into another fresh directory with fresh platform-resolved external state. POSIX may use a new absolute state override; Windows must use the fresh current user's canonical `FOLDERID_LocalAppData/video-replacer` and must not redirect it. In this clone, prove the setup Gate blocks task commands before READY, run the complete platform test entrypoint, then run both audits:

   - macOS: `.venv/bin/python tools/release_audit.py` and `.venv/bin/python tools/release_audit.py --history`
   - Windows: `.\.venv\Scripts\python.exe .\tools\release_audit.py` and `.\.venv\Scripts\python.exe .\tools\release_audit.py --history`

   Both audits must pass in the independent repository before any push. Do not push a legacy local history merely because its current payload passes.
6. Manually forward-test the exact [AGENT-INSTALL-PROMPT.md](AGENT-INSTALL-PROMPT.md) on a fresh macOS Apple Silicon user account against that same candidate commit. After explicit download/login approvals, confirm the Agent launches `setup login-codex-node`, the user only completes Codex account authorization, and Doctor proves the same stable external strict-file-auth home used by production. Confirm that home contains no `AGENTS.md`, rules, skills, plugins, MCP configuration, hooks or copied outer-Agent configuration. Retain native evidence that Doctor held one stable home lock and used the exact production command for both loopback phases: the `requires_openai_auth=false` capture observed one image-bearing request with zero top-level/additional tools, zero multi-agent hints and no auth header; the `requires_openai_auth=true` capture observed the same zero-tool surface and an authenticated handshake whose Bearer value matched stable `auth.json` by in-memory SHA-256 plus `hmac.compare_digest`. Confirm each captured model request was routed to loopback and stopped at HTTP 418 before a model response or inference, and that no raw token/header value was retained or logged. Treat unrelated process network activity as a separate observation boundary. Confirm the pinned Dreamina installer does not alter shell files or global skills, `setup verify` creates no remote task, and a second Agent session still receives live `ready: true`. Do not publish a release that only passes a mocked setup record or fixture-only wire test.
7. Complete the Windows hard Gate below for the same candidate commit. Then push only the independent clean-root history, protect the default branch, keep GitHub Actions permissions read-only, enable private vulnerability reporting, and tag the verified commit.

The sampled prompt-node implementation also needs deterministic evidence that the parent performs bounded chronological uniform-timestamp FFmpeg sampling, attaches only frames/references/structured JSON, sets `CODEX_EXEC_SERVER_URL=none`, grants no execution/filesystem tools, schema-validates the returned prompt string, and alone writes `prompt.txt`. Prove Doctor and production resolve the same stable external, instruction-free, strict-file-auth `CODEX_HOME`, setup never copies the outer auth per invocation, and all prompt-node Codex processes are serialized to avoid refresh-token races. READY must include both local zero-tool wire phases of the exact constructed command so managed/system MCP, hook, tool or multi-agent reinjection and divergence from the stable file-auth identity fail closed. Both captured model requests terminate at loopback HTTP 418 before a model response or inference; this does not attest unrelated process network activity. Keep the synthetic `prepare` forward-test as a separate required Gate.

## Windows 11 x64 hard Gate

Do not label a candidate Windows release-ready until every item below has fresh evidence for the exact commit. CI, mocked provider tests, and another candidate's evidence are insufficient. This checklist describes required future release evidence; its presence does not claim that the current candidate has passed it.

1. Use a real, current Windows 11 x64 machine and a fresh ordinary local user with no repository runtime, Dreamina project binary, node Codex home or Video Replacer setup record. Install or sign in to the native Codex Agent and include the preferred `windows.sandbox="elevated"` mode in the required coverage; its one-time administrator-approved setup is distinct from running the workflow as an OS administrator. WSL and Git Bash must not participate.
2. Clone the exact candidate into a path that contains both spaces and Chinese characters. Give a fresh Agent task the exact install prompt. The user may approve precise system/network changes and complete Dreamina OAuth/device login in the provider's protected UI, but must not run a repository command, edit JSON/env/profile, or relocate the clone.
3. Confirm the Agent uses `install.cmd`, `video-replacer.cmd`, and `video-replacer-test.cmd`; it must not permanently alter PowerShell execution policy. Before any repository-triggered Windows Codex execution, retain evidence that the candidate resolved a modern canonical `packages/standalone/releases/` package, validated `codex-package.json`, fetched the exact installed version's `https://releases.openai.com/codex/releases/<version>/release.json`, selected its single `codex-x86_64-pc-windows-msvc.exe` asset and matched the actual binary SHA-256. The setup identity must record the resulting `official_sha256` and matching release tag. Evidence based only on `.exe` suffix, a legacy layout, cached record, fixed version/digest or an offline/unreachable manifest fails this Gate. Confirm the Agent launches `.\video-replacer.cmd setup login-codex-node` only after provenance passes; the user only completes Codex account authorization. Exercise the explicit-login repair with a malformed regular `auth.json`: prove it is removed only after the exact locked home passes path, structure, native ACL and stable file-identity checks, then prove the login creates a strictly schema-valid replacement. Also prove a valid auth is preserved and that a link, nonregular auth, unsafe ACL or file-identity change prevents Codex from starting. If a trusted dependency install needs a separate UAC/administrator process, capture that one scoped approval, end that process, and prove setup continues inside the configured Codex sandbox without administrator-owned runtime or credentials.
4. Retain native Known Folder evidence that bootstrap, setup, Doctor and workflow all resolve the real fresh user's `FOLDERID_LocalAppData/video-replacer`. Prove a forged `LOCALAPPDATA` is ignored; an absent or canonically identical `VIDEO_REPLACER_STATE_DIR` succeeds; every redirect plus UNC, mapped-drive, non-fixed-drive and reparse-point candidates fail closed. Confirm the node home is on that local fixed-drive root and retain native owner/DACL evidence for the directory, `auth.json` and `.video-replacer-auth.lock`: owner is the fresh current user, inheritance is protected, and the only full-control allow ACEs are that user and `SYSTEM`. Confirm the home contains no `AGENTS.md`, rules, skills, plugins, MCP configuration, hooks or outer-Agent configuration; Doctor and production must resolve this same home. Capture native Doctor wire evidence from the actual host while one stable node-home lock remains held. Required check `codex-wire` must prove that `requires_openai_auth=false` sends one synthetic image-bearing request with zero top-level/additional tools, zero multi-agent hints and no auth/API-key header. Required check `codex-file-auth-wire` must prove that `requires_openai_auth=true` sends the same zero-tool image surface plus exactly one Bearer handshake whose in-memory SHA-256 matches the strictly validated stable `auth.json` `access_token` via `hmac.compare_digest`. Each captured model request must route to loopback and stop at HTTP 418 before a model response or inference, with no raw token or header value retained/logged. Any managed/system MCP, hook, tool or agent hint visible at either wire blocks READY. Use separate native network observation to establish whether the process attempted any unrelated connection during these phases; the wire attestation alone does not prove that condition. Confirm `setup login-dreamina` is the only Dreamina login launch path and the pinned Windows Dreamina `.exe` SHA-256 passes. Retain process evidence that install, Doctor, login/account, submit and query all receive the shared child-only restricted PATH plus `NoDefaultCurrentDirectoryInExePath`, that a cwd/PATH PowerShell or pwsh fixture is not launched by the pinned 1.4.15 bare-name ancestry probe, and that the real `version` and help checks remain bounded; do not describe this narrow mitigation as a general subprocess sandbox. Finally, live `.\video-replacer.cmd setup status --json` must re-fetch/re-hash Windows Codex provenance, repeat both loopback captures, and return `ready: true` without media upload, remote generation, task creation, or credit consumption.
5. Retain a native two-process contention trace against the same node home: while one process holds the auth lock, a second auth-bearing Codex status/wire process must wait and may proceed only after release. Prove the two processes never overlap access to the shared file-auth store. Close the first Agent task. In a new native Codex Agent session using the same outer-Agent sandbox mode, open the same path and prove live status again validates the existing strict file-auth home and returns `ready: true` without another credential copy or login. This is the cross-session node credential, backend credential and setup-record Gate.
6. In that second session, ingest a synthetic non-sensitive multi-Job batch in the same space-and-Chinese path and stop after `prepare`. Confirm the outer Agent may remain in the official `elevated` sandbox, while every inner sampled prompt process uses the stable node-only `CODEX_HOME`, `CODEX_EXEC_SERVER_URL=none`, no execution/filesystem tools, and no second elevated sandbox/home. Confirm prompt-node Codex processes are serialized with no overlap, the parent performs FFmpeg sampling and writes each `prompt.txt`, local mosaic capability works where requested, `PAUSE` remains, no paid command was called, and provider history/account evidence shows no media upload, generation task, or credit use.
7. Exercise both native Windows Codex outer-Agent sandbox modes without conflating them with OS administrator processes. The preferred `elevated` sandbox must perform the complete install, READY, second-session, and synthetic prepare path. In a separate `unelevated` fallback task, run no-cost status and Doctor compatibility checks; it must not run prompt preparation, and neither outer mode changes the inner prompt process's no-execution/file-auth-home contract. Do not submit, reinstall over the runtime, change ownership, or call the fallback stronger. Any separately approved UAC/administrator package-install process must remain narrow, terminate before setup verification, and leave no administrator-only file or credential dependency. Record OS build, architecture, Codex version, canonical package path, official release tag and SHA-256, outer sandbox mode, launcher output, redacted native wire-attestation/Doctor/setup evidence, and timestamps without copying credentials.

A failed item blocks the Windows support label for that release. It does not block continued implementation work or the Linux preview lane.

## Manual no-cost check

Each supported platform's release candidate must complete one synthetic local-only preparation path without backend upload. A real backend check stops after `prepare` unless a maintainer separately authorizes a known low-risk test batch. Never turn the release process into an unattended paid submission.
